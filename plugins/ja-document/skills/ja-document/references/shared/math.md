# math

数式を伴う説明の構成と数式表記の規範。

数式を説明の出発点にしない。
言葉、図、具体例で対象と対応関係を示してから、その関係を数式で圧縮する。
読者に記号の意味を式から逆算させず、説明の抽象度を一段ずつ上げる。

## 数式表記

数式は LaTeX 構文で書く。Markdown では、インライン数式を `$...$`、ディスプレイ数式を `$$...$$` で囲む。数式をコードブロックに入れず、プレーンテキストや疑似コード風の表記で書かない。

媒体によらず、記号の数学的な役割を見た目で区別する。

- ベクトルと行列は `\boldsymbol{...}` で表す。ラテン文字だけでなく、ギリシャ文字のベクトルにも同じ規則を適用する
- ベクトルの添字は太字の外へ置き、`\boldsymbol{x}_i` と書く。推定値や時刻も `\hat{\boldsymbol{x}}_i`、`\boldsymbol{x}_t` のように、対象となる記号だけを太字にする
- スカラー、添字、集合名は装飾しない。大文字であることだけを理由に太字にせず、確率変数がベクトル値または行列値である場合だけ太字にする
- 名前付きの演算は `\mathtt{...}` を使い、標準LaTeXコマンドがある演算はそのコマンドをそのまま使う
- 同じ対象を成分表示からベクトル・行列表記へ一般化するとき、記号の字体も一般化した段階で切り替える

文書を完成させた後、ベクトル・行列が通常の斜体のまま残っていないか、スカラーや添字まで誤って太字になっていないかを確認する。

## 変数一覧

数式を多用する節（理論や手法の定式化など）では、節の冒頭に変数一覧を置く。一覧では、変数を役割ごとにまとめ、各変数に次の3つを書く。

- 記号（LaTeX で書く）
- 何を表すか（1文で書く）
- 直感的な理解を助ける補足（具体例、値域、特殊な場合の振る舞いなど）

例：

```
入力として与えられるもの：

- $n$：入力テキストの文字数。ユーザーが渡したプロンプトの長さ
- $K$：モデルのコンテキストウィンドウの文字数。これを超える入力はモデルに直接入れられない

プランナーが決めるもの：

- $k^*$：各段でいくつに分割するか。たとえば $k^*=5$ なら、入力を5つのチャンクに分ける
- $\tau^*$：分割せずに LLM に直接渡すサイズの閾値。$\tau^*=26{,}000$ なら、26,000文字以下のチャンクはそのまま LLM に渡す
```

数式が少ない節では、一覧を置かず、数式の前後で変数を定義してよい。

## 構成手順

次の順序で一つの代表例を最後まで説明する。
対象に該当しない段階を省く場合は、前後の論理が飛ばないように文章で接続する。

1. この節で何を説明するかを予告する
2. 説明対象の最小単位を一つ取り出す
3. その最小単位を図または具体例で示す
4. 数式へ登場する記号を文章で定義する
5. 最小単位の計算を成分表示で書く
6. 式を文章で読み下す
7. 同じ構造を複数並べる
8. 添字の範囲を定義して一般化する
9. 最後にベクトルや行列で圧縮する
10. 一般式から得られる性質を説明する
11. 代表例を十分に説明してから、変種や別方式を紹介する

## 検査

完成後に次を確認し、満たさない箇所は構成手順の対応する段階へ戻って修正する。

- 節の冒頭だけで、説明対象と到達点が分かるか
- 最初の数式より前に、対象の最小単位を図または具体例で確認できるか
- すべての記号を初出前または初出直後に文章で定義しているか
- 和や積を使う前に、添字が何を数え、どの範囲を動くかを定義しているか
- 成分表示から一般式まで、各段階の対応関係を読者が追えるか
- 各式の直後に、その式が何を計算するかを文章で読み下しているか
- ベクトルや行列による表記を、理解の前提ではなく最後の圧縮として使っているか
- 一般式から性質を述べる際に、どの項または構造から導ける性質かを示しているか
- 代表例の説明を終える前に、変種や別方式を混ぜていないか
