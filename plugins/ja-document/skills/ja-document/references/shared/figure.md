# figure

図の描き方と、論文の図表の抽出と挿入の規範。

## TikZ の概念図

時間軸、処理の流れ、構造の模式図のように、データの値ではなく本文の説明から描く概念図は、TikZ で描く。TikZ は要素の位置を座標で指定でき、図の中に数式を組めるためである。

### 書体

- 図の中の文字と数式の書体は、[fonts.md](fonts.md) に従う。

### 色

- 図形は白で塗り、黒の輪郭を付ける。白い背景の上では、輪郭がないと図形の境界と、隣り合う区間の境目が見えないためである。白と黒以外の色は使わない。TikZ の既定色（青や赤）も使わない。
- 強調色の薄紫 `#BBBDFA` は、ユーザーが許可した場合だけ、許可された要素に使う。

### 文字の大きさ

- 1つの図の中のラベル（区間名、時点名、所要時間、軸の目盛り）は、すべて同じ大きさにする。大きさが違うと、ラベルの間に意図しない重要度の差があるように見えるためである。ノードごとに `\footnotesize` のような大きさを指定せず、図全体の設定（`every picture` の `font`）に任せる。

### 描く内容

- 本文で主張を述べている図には、その主張の要約や注記を描かない。ただし、ユーザーが求めた場合は描く。主張は本文が述べ、図には読み手が読み取る対象だけを置くためである。
- 本文で内訳や構造を説明し、その対象を示す図がある場合は、その内訳や構造も図に描き込む。本文の説明と図の要素を、読み手が対応させられるようにするためである。時間の内訳は、対象の区間の直下に、起きた順に並べる。
- 区間の親子関係と時間を1つの図に描くときは、子の区間の端を親の区間の端に揃える。揃わない場合は、その差に当たる処理を別の行として描く。子が親の内側に収まって見えれば、親子関係が時間の上でも読み取れる。一方、端がずれたまま説明がないと、読み手は差が何の時間かを判断できないためである。
- 計測データにない処理を、差を説明するために補って描くときは、破線の枠と白の塗りにし、親子関係の線にはつながない。計測データにある区間と、説明のために補った区間を、読み手が混同しないようにするためである。

### 線と配置

- 角で接する線（軸の端と目盛り、木構造の幹と枝）は、1本のパスとして描く。線の端は四角く延ばす設定（`line cap=rect`）にし、600dpi で書き出す。別々の線を角で出会わせると、線の太さの半分の四角が埋まらず角が欠ける。また、解像度が低いと線の幅がピクセルの整数倍にならず、縦の線と横の線で太さが違って見えるためである。
- 処理を行で表す図では、中身の異なる処理は、所要時間が同じでも1つの行や1つのラベルにまとめず、それぞれに名前を付けて別の行に描く。時間の流れを示す図では、行を起きた順に並べる。1つの行にまとめると、別々の処理が1つの処理に見えるためである。
- 図の要素（波括弧、線、ラベル）は互いに重ねない。区間を示す波括弧どうしは端点を共有させず、離れた位置に置く。重なると、どのラベルがどの区間を指すかが読めなくなるためである。
- 区間のラベルは波括弧の真下に置き、引き出し線は使わない。斜めの引き出し線は、ほかの波括弧や線と交差しやすいためである。

## 論文の図表の抽出と挿入

論文に掲載されている図 (Figure) と表 (Table) は、ゼロから再構築（手書きの HTML 表・SVG 図の作り直し）してはならない。原論文の図表をそのまま画像として抽出し、成果物（.md / HTML）に挿入する。手書き再構築は転記ミスを生み、原表の体裁（太字・下線・色分けの凡例等）も失われるため禁止する。

抽出には ja-document スキル同梱のスクリプトを使う。

```
uv run {ja-document スキルのディレクトリ}/scripts/extract_images.py <PDFパス>
```

- スクリプトは PDF 内の "Figure N" / "Table N" のキャプションを検出し、その直上の図表領域（ベクター図形・罫線・埋め込み画像のバウンディングボックス）を 300dpi でクリップ描画する。図表は多くがベクターで描かれ埋め込みラスタを持たないため、「埋め込み画像の取り出し」ではなく「領域のレンダリング」で抽出する点に注意
- 出力は既定で `{プロジェクトルート}/images-from-papers/` に `{論文ファイル名のベース}-fig{N}.png` / `{論文ファイル名のベース}-table{N}.png` として保存される。抽出一覧は同ディレクトリの `{ベース}-manifest.json` で確認できる
- 複数パネルを持つ図表（例: パネル (a)〜(f) を含む 1 つの Table フロート）は、原論文で 1 つのフロートなら 1 枚の画像として抽出される
- 抽出後、`images-from-papers/` 配下の画像を成果物に挿入する。.md では相対パスで `![図N](../images-from-papers/{ベース}-fig{N}.png)` のように参照する。自己完結型 HTML（html 等）では base64 データ URI として埋め込んでもよい
- 図表のキャプションは、画像の下に日本語訳した説明文を独立して添える。画像内のキャプション文字は原文のまま残る（再描画しない）ので、訳は画像外に置く
- まれにスクリプトが特定の図表を取りこぼす／余白を含みすぎる場合は、`--dpi` を上げる、あるいは出力画像を確認した上で個別に `pymupdf` のクリップ矩形を調整する。いずれの場合も「画像として抽出する」方針自体は崩さない
