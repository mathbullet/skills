# results

論文の詳細解説で、実験と数値結果を書くときの規範。

## 概念の初出の定義

- 詳細解説で初めて出てくる概念は、使う前に定義する。論文の中で定義されている概念を省略しない。
- 表や数値を示す前に、その数値を理解するために必要な概念を、すべて定義しておく。

## 数値結果

- 実験結果は、できるだけ表で示す。
- 比較対象（ベースライン）と提案手法の数値を並べて書く。
- 数値は、論文に書かれた値を正確に転記する。四捨五入や概算をしない。
- 表を示す前に、各列、各指標が何を測っているかを箇条書きで定義する。読み手が表の数値を見る時点で、各列の意味が分かっている必要があるためである。
- 「精度」「性能」のような汎用の語を使わず、論文で定義されている指標名（分類正答率、pass rate、pass@1 など）をそのまま使う。
- 同じ語が文脈によって異なる意味で使われている場合は、その多義性を明記する（例：手法名が、表の中では最良の単一の結果を指し、本文では手順全体を指す場合）。

## 実験の手順

実験の章では、読み手が「何を、どういう手順で行ったのか」を追えるように、次を省略せずに書く。

- タスクの具体的なステップ（入力は何か、各ステップで何が起きるか、何が出力されるか）
- データ分割の構造（search set、validation set、test set などがある場合は、それぞれの役割と、どの結果がどの分割での値か）
- 探索や最適化の手順がある場合は、その構成（初期状態に何を入れたか、何回反復したか、各反復で何が生成されるか、最終的にどの基準で結果を選んだか）

## 実験の章の独立性と粒度

- 各実験の章は、前の章を読まなくても理解できるように書く。手法の章で導入した概念を、実験の章で説明なしに省略形で使わない。同じ探索手順でも、各実験の章で、その実験に固有のパラメータとともに書く。
- 実験の章が複数ある場合は、記述の粒度を揃える。ある実験では探索手順を丁寧に書き、別の実験では1文で済ませる、という不統一をしない。
