# translation

訳語の決め方と、専門用語の示し方の規範。

## 訳語の決め方

語は、辞書の訳語を当てはめて決めるのではなく、その分野の日本語の書き手が実際にどう書くかという言語運用の常識に従って決める。ここでいう専門用語は、分野で特定の意味を持つ語と、原文の著者が名付けた語を指す。

訳語は、次の優先順位で決める。

1. 現在の会話でユーザーが明示した表現
2. プロジェクト固有の用語
3. 対象分野で定着した用語

- 専門用語は、その分野の日本語圏で通用している訳語を使う。
- 定訳のない語は、原語のまま書く。
- 原語をカタカナで書くのが日本語で普通になっている語は、カタカナで書く。たとえば tool は、物理的な道具でなく、特にソフトウェアを指す場合は、ほとんど「ツール」と書かれる。
- 訳語は、原文の語がその文脈で担っている意味の範囲に合うものを選ぶ。日常語の訳語が、原文の語より広い意味や弱い意味に読める場合は、意味の限定された語に替える。
- 同じ内容を表す語が複数あるときは、日常会話で使う語ではなく、書き言葉や研究の文脈で使う語を選ぶ（例：「良い」ではなく「優れた」、「伸びすぎる」ではなく「過剰に伸びる」、「仕事」ではなく「役割」、「理解されていない」ではなく「解明されていない」）。
- 2つの状態を比べる述語は、比べている軸に合わせて選ぶ。同じ時点にある2つのものの違いは「異なる」で述べ、以前の状態から現在の状態への時間の経過による変化は「変わる」で述べる。
- 同じものに複数の版（公開された当初の版と、後から作り直した版など）があるときは、どの版を指すかが紛れない語を選ぶ。「元の」は直前に述べた状態を指すとも読めるので、公開された当初の版は「オリジナルの」と書く。
- 専門用語は、初出の箇所で「日本語（English）」の形で示す。見出しで示した場合は、本文で繰り返さなくてよい。
- 原文の著者が独自に名付けた語は、「著者が〜と呼ぶ」と書いて、分野の既存の専門用語と区別する。
- 原文が専門用語を独特の範囲で使っている場合は、その範囲を括弧で補足する。
- 略号は、正式名を見出しか本文で先に出してから使う。
- 原文が語を新しく定義している箇所は、「原文は〜を X と呼ぶ」のように、定義であることが分かる文型で書く。「〜を X として数える」のような書き方では、語の定義なのか手順の説明なのかが分からない。
- 原文が定義していない語を、書き手が作って導入しない。原文にない呼び名が必要に見える場合も、呼び名を作らず、対象を説明する文で書く。
- 単語の表面的な対応だけで、独自の圧縮熟語を作らない。
- 訳語だけを読んで意味が通らない直訳を使わない。
- ユーザーが指定した用語を、勝手に言い換えない。
- 文書の中で、同じ概念の訳語を揺らさない。
- 実験条件名、関数名、変数名のような識別子は、識別子のまま書く。
