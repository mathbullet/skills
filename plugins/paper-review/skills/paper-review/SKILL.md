# Paper Review

論文の詳細レビュー（.md）を作成する際に従うべき規範。

## 1. 成果物の構造

### 1.1 冒頭

以下の順に記載する:

1. タイトル（`# {論文タイトル} レビュー`）
2. 書誌情報（著者、所属、venue、年、arXiv/DOI、URL）
3. アブストラクトの全文引用（英語原文をブロック引用で掲載し、直後に独立した段落として日本語訳を置く）

### 1.2 本文の見出し構成

生成するドキュメントの見出し構成は元の論文のセクション構成に従う。論文が Section 1: Introduction, Section 2: Method, Section 3: Results, ... という構成であれば、レビューも同じ順序・同じ見出しで構成する。

レビュー独自のセクション（「論文の強み」「論文の限界」「ソース一覧」等）は、論文のセクション構成の後に追加する。

### 1.3 箇条書きと地の文の使い分け

内容の性質に応じて形式を選ぶ:

- 箇条書きが適切な場面: 並列的な要素の列挙（変数一覧、評価指標の定義、表の列の説明、手法の比較ポイントなど）。内容が羅列的であるなら箇条書き構文を使う。羅列的な内容を地の文の段落として書くと、各要素の区切りが見づらく、形式と内容が合わない
- 地の文が適切な場面: 要素間の関係、議論の流れ、因果関係、文脈の説明など。なぜそれらが並置されているのか、全体としてどういう議論を構成しているのかを伝える必要がある場合

## 2. 典拠の明示

レビュー中のすべての事実的記述には、それが論文のどこに基づくかを明示する。典拠のない記述は検証不能であり、レビューとしての価値がない。

- 参照は `[著者略称, YYYY/MM]` の形式で本文中に記載する（例: `[ProTeGi, 2023/05, Section 2.1]`）
- セクション番号、ページ番号、Table/Figure 番号のいずれかで位置を特定する
- 番号参照（`[1]`, `[2]` 等）は使わない
- 論文が言及している個々の文献を省略しない。Related Work等で複数の文献が挙げられている場合、それらを「○○など」とまとめず、著者名・年を付けて個別に記載する。レビューの読者にとって関連文献の一覧は重要な情報であり、レビュー対象論文のセクション・ページへの参照で代替できるものではない

## 3. 引用の明示

論文の主張を正確に伝えるために、原文引用をブロック引用で掲載する。要約だけでは、書き手の解釈が正しいか読み手が判断できない。

- 引用の直後に `[著者略称, YYYY/MM, 位置]` を付す
- 英語の引用には必ず日本語訳を付記する。引用ブロックの直後に独立した段落として訳文を置く。括弧で囲んで原文に併記する形式は使わない
- 引用と地の文（書き手の要約・解釈）を明確に区別する

## 4. 数式の記載

### 4.1 構文

- 数式は LaTeX 構文で記載する。インライン数式は `$...$`、ディスプレイ数式は `$$...$$` で囲む
- 厳禁: 数式をコードブロック（``` ``` ```）に書くこと。数式に LaTeX 構文以外（プレーンテキスト表記、疑似コード風表記等）を使うこと

### 4.2 変数の定義

数式中の変数は、読者にとって未知の記号である。数式を提示する前に、その数式に含まれるすべての変数・記号の意味を定義する。定義なしに数式だけを置いてはならない。

数式を多用するセクション（理論・手法の定式化等）では、セクション冒頭に変数一覧を置く。一覧では変数を役割別にグループ化し、各変数に以下を記載する:

- 記号（LaTeX表記）
- 何を表すか（一文の説明）
- 直感的な理解を助ける補足（具体例、値域、特殊ケースでの振る舞い等）

例:

```
入力として与えられるもの:

- $n$: 入力テキストの文字数。ユーザーが投げたプロンプトの長さ
- $K$: モデルのコンテキストウィンドウの文字数。これを超える入力はモデルに直接入れられない

プランナーが決めるもの:

- $k^*$: 各段でいくつに分割するか。例えば $k^*=5$ なら入力を5つのチャンクに割る
- $\tau^*$: 分割しないでLLMに直接投げるサイズの閾値。$\tau^*=26{,}000$ なら、26,000文字以下のチャンクはそのままLLMに渡す
```

数式が少ないセクションでは、一覧を設けず数式の前後で変数を定義してもよいが、未定義の変数を含む数式を提示してはならないという原則は同じである。

## 5. 数値結果の記載

- 実験結果はできるだけ表形式で記載する
- 比較対象（ベースライン）と提案手法の数値を並記する
- 数値は論文に記載された値を正確に転記する。四捨五入や概算をしない
- 表を掲載する前に、各列・各指標が何を測定しているかを箇条書きで定義する。読者が表の数値を見る時点で、各列の意味が明確になっている必要がある
- 「精度」「性能」のような汎用語を安易に使わない。論文中で定義されている具体的な指標名（分類正答率、pass rate、pass@1 等）をそのまま使う
- 同一の用語が文脈によって異なる意味で使われている場合（例: 手法名が表中では最良の単一結果を指し、本文では手順全体を指す等）、その多義性を明記する

## 6. 実験記述の原則

### 6.1 手順の明示

実験セクションでは、読者が「何をどういう手順でやったのか」を追えるように書く。以下を省略しない:

- タスクの具体的なステップ（入力は何か、各ステップで何が起きるか、何が出力されるか）
- データ分割の構造（search set / validation set / test set 等がある場合、それぞれの役割と、どの結果がどの分割上の値か）
- 探索・最適化の手順がある場合、その構成（初期状態に何を入れたか、何イテレーション回したか、各イテレーションで何が生成されるか、最終的にどの基準で結果を選択したか）

### 6.2 セクション間の独立性

各実験セクションは、前のセクションを読まなくても理解できるように書く。Method セクションで導入した概念を、実験セクションで説明なしの省略形で使わない。同じ探索手順でも、各実験セクションでその実験固有のパラメータとともに記述する。

### 6.3 記述粒度の統一

複数の実験セクションがある場合、記述の粒度を揃える。ある実験では探索手順を丁寧に書き、別の実験では一文で済ませる、といった不統一をしない。

### 6.4 概念の初出定義

レビュー中で初めて登場する概念は、使用する前に定義する。論文中で定義されている概念を省略してはならない。特に、表や数値を提示する前に、その数値を理解するために必要な概念がすべて定義済みであることを確認する。

## 7. 禁止事項

- 論文に書かれていない解釈・推測・関連づけを書かない
- 「この手法は○○に応用できる」「○○との関連が示唆される」等の独自の接続を付加しない
- レビュー対象の論文の内容記述に徹する。会話の文脈や他のプロジェクトとの関連は書かない

## 8. ソース一覧の書式

レビュー末尾にソース一覧を記載する。形式は以下の通り:

```
[参照ラベル, YYYY/MM] 著者. "タイトル." 媒体名. URL
```

`- [番号]` のリスト形式は使わない。

レビュー対象の論文に加え、レビュー内で言及した他の論文もソース一覧に含める。
